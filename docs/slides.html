01

journey ยาวที่สุดในเอกสาร — 8 ขั้นตอน

ได้ฝึกครบทั้ง CRUD, validation, การจัดการสถานะ และ edge case มากกว่าระบบจองคิวที่จบใน 3 ขั้นตอน

02

เป็นปัญหาที่เจอจริง ไม่ใช่โจทย์สมมติ

การซื้อรถคือการตัดสินใจครั้งใหญ่ของคนทำงาน แต่ข้อมูลยังกระจัดกระจายและต้องเดินหลายโชว์รูม

คำถามข้อ 4

มี feature อะไรต่างจากระบบอื่น

ต่างข้อที่ 1

ล็อกราคาให้ผู้ซื้อ 14 วัน

ออกใบจองแล้วล็อกทั้งราคาและโปรโมชั่น ต่อให้โปรฯ หมดอายุทีหลัง ใบจองใบนั้นก็ยังได้ราคาเดิม

ต่างข้อที่ 2

สินเชื่อไม่ผ่านแล้วไปต่อได้

ระบบทั่วไปขึ้นแค่ “ไม่อนุมัติ” ของเราคำนวณให้เลยว่าต้องเพิ่มดาวน์กี่บาท หรือยืดเป็นกี่งวด ถึงจะผ่านเกณฑ์

ต่างข้อที่ 3

คิวทดลองขับชนกันไม่ได้

มีคนจองเวลาเดียวกันตัดหน้า ระบบตอบ 409 แล้วรีเฟรชคิวว่างให้ใหม่ ไม่รับจองซ้อนแล้วโทรมายกเลิกทีหลัง

ต่างข้อที่ 4

ตรวจสิทธิ์จริง ไม่ใช่แค่มีหน้า login

ผู้ใช้ยกระดับตัวเองเป็น admin ไม่ได้ · ถูกระงับบัญชีแล้ว token ตายทันที · ลบ admin คนสุดท้ายไม่ได้

ส่งงานสัปดาห์นี้

REST API 10 endpoint

1 · Authentication

  • POST/api/registerสมัครสมาชิก
  • POST/api/loginเข้าสู่ระบบ
  • POST/api/logoutออกจากระบบ
  • POST/api/change-passwordเปลี่ยนรหัสผ่าน

2 · User Management

  • GET/api/meข้อมูลตัวเอง
  • GET/api/usersทั้งหมด + pagination
  • GET/api/users/{id}รายคน
  • PUT/api/users/{id}แก้ไข
  • DELETE/api/users/{id}ลบ (admin)
  • GET/api/check-username/{name}เช็คชื่อซ้ำ
