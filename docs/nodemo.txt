# สคริปต์นำเสนอ 5 นาที — แบบพูดล้วน ไม่ต้องเปิดเว็บ

ใช้เมื่อ **ไม่ได้ต่อจอ / ไม่มีเน็ต / เครื่องรันไม่ขึ้น / อาจารย์ให้พูดอย่างเดียว**
อ่านตามได้เลย ไม่ต้องเปิดอะไรทั้งสิ้น (ถ้ามีจอให้ฉาย ก็เปิด `docs/slides.html` ประกอบได้ — สไลด์ที่ตรงกันระบุไว้ท้ายหัวข้อ)

**เวลารวม ~4 นาที 40 วินาที** เผื่อเวลาพูดช้า/มีคนถามแทรกไว้ 20 วินาที

| ช่วง | หัวข้อ | เวลา |
|---|---|---|
| 1 | อุตสาหกรรม + ปัญหา | 50 วินาที |
| 2 | โปรเจกต์ทำอะไร | 55 วินาที |
| 3 | ทำไมเลือกโปรเจกต์นี้ | 60 วินาที |
| 4 | feature ที่ต่างจากระบบอื่น | 70 วินาที |
| 5 | สิ่งที่ส่งสัปดาห์นี้ (API + Docker) | 45 วินาที |
| 6 | สรุป | 20 วินาที |

> **วิธีใช้:** ประโยคที่ขีดเส้นใต้ในใจคือประโยคที่ห้ามลืมพูด ส่วนที่เหลือถ้าเวลาเหลือน้อยตัดได้
> เครื่องหมาย `⏸` คือจุดที่ควรหยุดหายใจ 1 วินาที ไม่ใช่พูดรวด

## 1 · อุตสาหกรรม + ปัญหา — 50 วินาที
*(สไลด์ 02–03)*

> "สวัสดีครับ กลุ่มของผมทำ User Journey ที่ 15 อยู่ใน **อุตสาหกรรมยานยนต์** ครับ
> โจทย์คือ **การจองทดลองขับและซื้อรถออนไลน์** ⏸
>
> จริง ๆ แล้วงานนี้คาบเกี่ยวสามอุตสาหกรรมครับ — หลักคือยานยนต์ คือฝั่งโชว์รูมและตัวแทนจำหน่าย
> อันที่สองคือ **ค้าปลีกสินค้าราคาสูง** เพราะรถหนึ่งคันราคาหลักล้าน คนซื้อใช้เวลาตัดสินใจเป็นเดือน
> และอันที่สามคือ **การเงินและสินเชื่อ** เพราะเกือบทุกดีลจบด้วยการจัดไฟแนนซ์ ⏸
>
> Persona ของเราคือคนทำงานที่อยากได้รถสักคัน แต่ยังไม่กล้าตัดสินใจ เพราะเจอปัญหาสามข้อ
>
> หนึ่ง — **เทียบรุ่นไม่ได้จริง** สเปคกับราคาอยู่คนละเว็บคนละโบรชัวร์ ต้องจดใส่กระดาษเอง
> สอง — **ไม่รู้ว่าผ่อนเดือนละเท่าไร** จนกว่าจะไปนั่งคุยกับเซลส์
> สาม — **ยื่นสินเชื่อไปแล้วเงียบ** ไม่มีที่ให้เช็คสถานะ ได้แต่รอเขาโทรกลับ ⏸
>
> สามข้อนี้คือที่มาของโปรเจกต์ครับ"

## 2 · โปรเจกต์ทำอะไร — 55 วินาที
*(สไลด์ 04)*

> "ระบบของเราชื่อ **ASTRA Motors** ครับ เป็นเว็บแอปที่ทำให้ขั้นตอนการซื้อรถจบได้บนเว็บ
> ทั้ง **8 ขั้นตอน** โดยไม่ต้องเข้าโชว์รูมจนกว่าจะถึงวันทดลองขับจริง ⏸
>
> ขั้นที่หนึ่ง เปรียบเทียบรุ่นรถแบบเคียงข้างกัน สูงสุดสามรุ่นพร้อมกัน
> ขั้นที่สอง เข้าไปดูรายละเอียดรุ่น เลือกสีเลือกออปชัน ราคาอัปเดตทันทีที่กด
> ขั้นที่สาม เครื่องคำนวณไฟแนนซ์ เทียบเงินดาวน์กับงวดผ่อนจากสี่สถาบัน
> ขั้นที่สี่ จองทดลองขับ เลือกโชว์รูมและเวลาจากคิวที่ว่างจริง ⏸
> ขั้นที่ห้า วางเงินจองออนไลน์ ระบบออกใบจองและล็อกราคาให้
> ขั้นที่หก ยื่นขอสินเชื่อพร้อมแนบเอกสาร
> ขั้นที่เจ็ด ติดตามสถานะว่าอนุมัติหรือยัง
> และขั้นที่แปด นัดวันรับรถพร้อมรายการเอกสารที่ต้องเตรียม ⏸
>
> เทคโนโลยีที่ใช้คือ **FastAPI ฝั่ง backend** กับ **HTML CSS JavaScript ธรรมดาฝั่งหน้าเว็บ**
> ไม่มี framework ไม่มี build step และทั้งระบบรันด้วย **Docker Compose** ครับ"

## 3 · ทำไมถึงเลือกโปรเจกต์นี้ — 60 วินาที
*(สไลด์ 05)*

> "มีสี่เหตุผลครับ ⏸
>
> **เหตุผลที่หนึ่ง — journey นี้ยาวที่สุดในเอกสาร** มีถึง 8 ขั้นตอน
> เทียบกับระบบจองคิวทั่วไปที่จบใน 3 ขั้นตอน การเลือกอันนี้แปลว่าเราจะได้ฝึกครบ
> ทั้ง CRUD, การ validate ข้อมูล, การจัดการสถานะ และการรับมือ edge case มากกว่า ⏸
>
> **เหตุผลที่สอง — เป็นปัญหาที่เจอจริง ไม่ใช่โจทย์สมมติ**
> การซื้อรถคือการตัดสินใจใหญ่ที่สุดครั้งหนึ่งของคนทำงาน แต่ข้อมูลกลับกระจัดกระจายที่สุด ⏸
>
> **เหตุผลที่สาม — มีตรรกะทางธุรกิจให้เขียนจริง**
> ยอดผ่อน ดอกเบี้ย เงินดาวน์ เงื่อนไขการคืนเงิน เกณฑ์อนุมัติสินเชื่อ
> ทำให้ฝั่ง backend ได้เขียนการคำนวณจริง ๆ ไม่ใช่แค่รับข้อมูลจากฟอร์มไปเก็บลงตาราง ⏸
>
> **เหตุผลที่สี่ — ต่อยอดได้ตรงกับแผนของวิชา**
> สัปดาห์แรกเราทำหน้าจอกับ mock data สัปดาห์นี้ทำ REST API ระบบสมาชิก
> สัปดาห์หน้าย้ายลง PostgreSQL แล้ว deploy ขึ้นอินเทอร์เน็ตจริงครับ"

## 4 · มี feature ต่างจากระบบอื่นไหม — 70 วินาที
*(สไลด์ 06)*

> "มีครับ ผมขอยกสี่อย่างที่เว็บโชว์รูมทั่วไปไม่ทำ ⏸
>
> **ข้อที่หนึ่ง — เราล็อกราคาให้ผู้ซื้อ**
> เว็บส่วนใหญ่บอกแค่ราคา ณ วันนี้ ของเราพอออกใบจอง ระบบจะ **ล็อกทั้งราคาและโปรโมชั่นไว้ 14 วัน**
> ต่อให้โปรโมชั่นหมดอายุไปแล้วหลังจากนั้น ใบจองใบนั้นก็ยังได้เงื่อนไขเดิม
> เพราะเราเก็บราคาที่ล็อกไว้ติดกับใบจอง ไม่ได้ไปอ่านราคาปัจจุบันใหม่ทุกครั้ง ⏸
>
> **ข้อที่สอง — คนที่สินเชื่อไม่ผ่าน ยังไปต่อได้**
> ระบบทั่วไปขึ้นแค่คำว่า 'ไม่อนุมัติ' แล้วจบ ของเราคำนวณย้อนกลับให้เลยว่า
> ต้อง **เพิ่มเงินดาวน์อีกกี่บาท** หรือ **ยืดจากกี่งวดเป็นกี่งวด** ยอดผ่อนถึงจะไม่เกิน 40% ของรายได้
> แล้วเสนอแผนของสถาบันอื่นที่ผ่านเกณฑ์ พร้อมตัวเลขยอดผ่อนกำกับให้ด้วย ⏸
>
> **ข้อที่สาม — คิวทดลองขับชนกันไม่ได้**
> ถ้ามีคนจองเวลาเดียวกันตัดหน้าไปก่อน ระบบตอบกลับ 409 แล้วรีเฟรชคิวว่างให้ใหม่ทันที
> ไม่ใช่รับจองซ้อนไว้ก่อนแล้วค่อยโทรมายกเลิกทีหลัง ⏸
>
> **ข้อที่สี่ — ระบบสมาชิกของเราตรวจสิทธิ์จริง ไม่ใช่แค่มีหน้า login สวย ๆ**
> ผู้ใช้ทั่วไปแก้ role ตัวเองเป็น admin ไม่ได้ ระบบตอบ 403
> พอ admin สั่งระงับบัญชี token ที่ค้างอยู่ตายทันที ไม่ใช่รอหมดอายุ
> และระบบกันไม่ให้ลบ admin คนสุดท้ายในระบบ กับกันไม่ให้ลบบัญชีตัวเอง
> ทั้งหมดนี้เรามีเทสต์อัตโนมัติ **15 เคส** คุมไว้ครับ"

## 5 · สิ่งที่ส่งสัปดาห์นี้ — 45 วินาที
*(สไลด์ 07–08)*

> "งานที่ส่งสัปดาห์นี้คือ **REST API ระบบสมาชิกและจัดการข้อมูลผู้ใช้ รวม 10 endpoint** ครับ ⏸
>
> กลุ่มแรกคือ Authentication สี่ตัว — สมัครสมาชิก เข้าสู่ระบบ ออกจากระบบ และเปลี่ยนรหัสผ่าน
> กลุ่มที่สองคือ User Management หกตัว — ดูข้อมูลตัวเอง ดูผู้ใช้ทั้งหมดแบบแบ่งหน้า
> ดูรายคน แก้ไข ลบ และตรวจว่า username ซ้ำหรือยัง ⏸
>
> เรื่องความปลอดภัย **รหัสผ่านไม่ได้เก็บเป็นข้อความธรรมดา** เราแฮชด้วย PBKDF2 หนึ่งแสนสองหมื่นรอบ
> พร้อม salt แยกรายบัญชี และไม่เคยส่ง hash ออกทาง API เลย
> การยืนยันตัวตนใช้ Bearer token อายุ 8 ชั่วโมง ⏸
>
> ส่วนการรัน เราใช้ **Docker Compose สอง service** —
> ตัวแรกคือ web เป็น FastAPI ที่ทำหน้าที่ทั้งเป็น API และ serve หน้าเว็บในคอนเทนเนอร์เดียว
> ตัวที่สองคือ db เป็น PostgreSQL ที่มี healthcheck และเก็บข้อมูลไว้ใน volume
> web จะรอจน db พร้อมก่อนถึงจะสตาร์ต ⏸ **สั่ง `docker compose up` ครั้งเดียวขึ้นทั้งระบบ
> และรันได้เหมือนกันทุกเครื่องครับ**"

---

## 6 · สรุป — 20 วินาที
*(สไลด์ 10)*

> "สรุปนะครับ กลุ่มเราอยู่ในอุตสาหกรรมยานยนต์ ทำเว็บซื้อรถออนไลน์ที่ครบทั้ง 8 ขั้นตอนของ journey
> สัปดาห์นี้ส่ง REST API ระบบสมาชิก 10 endpoint จัดการด้วย Docker Compose
> จุดที่ต่างจากระบบอื่นคือการล็อกราคาให้ผู้ซื้อ ทางเลือกเมื่อสินเชื่อไม่ผ่าน และการตรวจสิทธิ์ที่ทดสอบไว้จริง
> สัปดาห์หน้าจะย้ายข้อมูลลง PostgreSQL แล้ว deploy ขึ้นใช้งานจริงครับ ⏸ ขอบคุณครับ"

## เวอร์ชันย่อ 3 นาที (ถ้าโดนตัดเวลา)

พูดเฉพาะ 4 ย่อหน้านี้:

1. **อุตสาหกรรม (20 วินาที)** — "ยานยนต์ครับ ทำระบบจองทดลองขับและซื้อรถออนไลน์ คาบเกี่ยวกับค้าปลีกสินค้าราคาสูงและสินเชื่อ ปัญหาคือคนซื้อรถเทียบข้อมูลไม่ได้ ไม่รู้ยอดผ่อนจนกว่าจะเจอเซลส์ และยื่นสินเชื่อแล้วเช็คสถานะไม่ได้"
2. **ทำอะไร (40 วินาที)** — "เว็บที่ทำ journey การซื้อรถให้จบได้ครบ 8 ขั้นตอน ตั้งแต่เทียบรุ่น คำนวณไฟแนนซ์ จองทดลองขับ วางเงินจอง ยื่นสินเชื่อ ติดตามผล จนถึงนัดรับรถ ใช้ FastAPI กับ HTML/CSS/JS ธรรมดา รันด้วย Docker Compose"
3. **ทำไมเลือก (50 วินาที)** — เหตุผลที่ 1 กับ 3 (journey ยาวสุด ได้ฝึกครบ + มี business logic ให้คำนวณจริง)
4. **ต่างยังไง (60 วินาที)** — ข้อ 1 กับ ข้อ 2 (ล็อกราคา 14 วัน + สินเชื่อไม่ผ่านแล้วคำนวณทางเลือกให้)

## ถ้าอาจารย์ขอให้เปิดจอกลางคัน

พูดต่อได้ทันทีโดยไม่ต้องรอเครื่อง:

> "ตอนนี้ยังไม่ได้เปิดเครื่องไว้ครับ แต่โค้ดทั้งหมดอยู่บน GitHub ที่ **github.com/Etihw175/astra-motors**
> ถ้าเปิดเครื่องได้ ผมใช้เวลาประมาณ 20 วินาที สั่ง `docker compose up` แล้วเข้าหน้า
> `localhost:8000/docs` ซึ่งเป็น Swagger UI ที่ FastAPI สร้างให้อัตโนมัติ กดยิงทดสอบทุก endpoint ได้เลยครับ"

ระหว่างรอเครื่อง ให้เล่าเคสเดโมปากเปล่าไปก่อน:

> "เคสที่ผมจะโชว์คือ ล็อกอินด้วยบัญชีลูกค้าธรรมดา แล้วลองยิง `PUT /api/users/` ของตัวเอง
> โดยส่ง `role` เป็น `admin` เข้าไป ระบบจะตอบ **403** กลับมา —
> เป็นการยืนยันว่าผู้ใช้ยกระดับสิทธิ์ตัวเองไม่ได้ครับ"

## ตัวเลขที่ต้องจำให้แม่น (เผื่อโดนถาม)

| เรื่อง | ตัวเลข |
|---|---|
| endpoint สัปดาห์นี้ | 10 (auth 4 + user management 6) |
| เทสต์อัตโนมัติ | 15 เคส ผ่านทั้งหมด |
| ขั้นตอนใน journey | 8 |
| ล็อกราคา | 14 วัน |
| คืนเงินจองเต็มจำนวน | ยกเลิกภายใน 7 วัน |
| เกณฑ์อนุมัติสินเชื่อ | ยอดผ่อน ≤ 40% ของรายได้ต่อเดือน |
| แฮชรหัสผ่าน | PBKDF2-HMAC-SHA256 120,000 รอบ + salt รายบัญชี |
| อายุ token | 8 ชั่วโมง |
| คอนเทนเนอร์ | 2 — web (พอร์ต 8000) + db (พอร์ต 5433) |
