## ส่วนที่เสร็จแล้ว

- **ฐานข้อมูลจริง** — ย้ายข้อมูลทั้งหมดจาก in-memory ลง PostgreSQL ผ่าน SQLModel (13 ตาราง), SQLite สำรองตอนรันในเครื่อง,
  seed แคตตาล็อก/บัญชีตัวอย่างอัตโนมัติ, `/api/health` เช็คการเชื่อมฐานข้อมูลจริง
- **ผูกทุกการจองเข้ากับบัญชี** — ใบจอง/สินเชื่อ/นัดศูนย์ต้องล็อกอิน, ทดลองขับจองแบบ guest ได้,
  เจ้าของหรือ admin เท่านั้นที่เห็นข้อมูล, รหัสจองเป็นแบบสุ่ม (เดาของคนอื่นไม่ได้)
- **ขั้นตอน 1–2** — รวมโปรโมชั่นที่ยังใช้ได้, ค้นหา/กรอง/เรียงลำดับรถในฐานข้อมูล, คะแนนรีวิวบนการ์ดรถ
- **ขั้นตอน 3** — โมเดล 3D 360°, เปรียบเทียบรุ่น, คำนวณไฟแนนซ์, จำลองการใช้งานบนถนนไทย, รีวิวรายรุ่น
- **ขั้นตอน 4** — คิวทดลองขับเรียลไทม์จากการจองจริง กันจองซ้อน ยกเลิกแล้วคิวกลับมาว่าง
- **ขั้นตอน 5** — วางเงินจอง ล็อกราคา, อัปโหลดเอกสารจริง (ตรวจชนิดไฟล์จาก magic bytes, ≤ 5 MB),
  ยื่นสินเชื่อ ผลพิจารณาบันทึกลงฐานข้อมูล + คำนวณทางเลือกเมื่อไม่ผ่าน + ยื่นใหม่ได้
- **ขั้นตอน 6** — หน้า "การจองของฉัน" รวมทุกอย่างของบัญชี, กระดิ่งแจ้งเตือนทุกหน้า (poll 15 วินาที) + toast
- **ขั้นตอน 7** — รีวิว 1–5 ดาว (ป้ายผ่านการใช้งานจริง), นัดเข้าศูนย์บริการ (จำกัด 2 คันต่อช่วงเวลา),
  คะแนนสะสม + ระดับสมาชิก + แลกของรางวัล, ยกเลิก/ลบแล้วหักคะแนนคืน
- **Event-driven** — Notification service และ Loyalty service รับ event จาก service อื่นผ่าน `events.py`
- **เทสต์** — 41 เคสผ่านทั้ง SQLite และ PostgreSQL 16
- **เอกสาร** — [`ARCHITECTURE.md`](ARCHITECTURE.md) (Microservices architecture + Technology stack + ER diagram),
  [`user-journey.md`](user-journey.md)

## ส่วนที่ยังไม่เสร็จ

| รายการ | สถานะ | แผน |
|---|---|---|
| Deploy ขึ้น URL สาธารณะ (Render/Railway) | ยังไม่ทำ | ต่อ repo กับ Render → Dockerfile path `backend/Dockerfile`, context `.` + สร้าง PostgreSQL แล้วตั้ง `DATABASE_URL` |
| วิดีโอรีวิวรถในหน้ารายละเอียด (ขั้นตอน 3) | ยังไม่ทำ | มีโมเดล 3D 360° แทนแล้ว — เพิ่มฟิลด์ `video_url` ในตาราง `cars` |
| ชำระเงินจริง / ส่งอีเมล-SMS จริง | จำลอง | เชื่อม payment gateway (เช่น Omise) และบริการส่งอีเมล ผ่าน event เดิม (`reservation.created`) |
| แยก service เป็นคนละ container | ออกแบบไว้แล้ว | เปลี่ยน event bus เป็น RabbitMQ + ตั้ง API gateway (Nginx/Traefik) route ตาม prefix |
| หน้าหลังบ้านพนักงานโชว์รูม | ยังไม่ทำ | มีแค่หน้าจัดการผู้ใช้ของ admin — เพิ่มหน้าดูคิวทดลองขับ/ใบจอง/นัดศูนย์ของแต่ละสาขา |
| Database migration (Alembic) | ยังไม่ทำ | ตอนนี้สร้างตารางด้วย `create_all` — เปลี่ยนโครงสร้างตารางต้องลบฐานข้อมูลเก่า |
| Usability test กับผู้ใช้จริง | ยังไม่ทำ | ให้ผู้ใช้ 3–5 คนลองทำครบ 7 ขั้นตอนแล้วเก็บ feedback |
| แจ้งเตือนแบบ push ทันที (WebSocket/SSE) | ใช้ polling | ตอนนี้หน่วงไม่เกิน 15 วินาที |
